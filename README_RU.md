# ECHO MEDIC — полная папка проекта

Рабочий браузерный прототип автономной диагностики космического модуля. Все вычисления выполняются локально в браузере. API-ключи, Python, платные сервисы и установка npm-пакетов не нужны. Для локального сервера требуется Node.js 20 или новее.

## Быстрый запуск в Windows

1. Распакуй архив полностью. Не запускай файлы внутри ZIP.
2. Открой папку ECHO-MEDIC в VS Code.
3. В меню Terminal → New Terminal введи:

```bash
npm start
```

4. Открой http://localhost:3000.
5. Чтобы остановить сервер, нажми Ctrl+C в терминале.

Также можно дважды нажать START_WINDOWS.bat при установленном Node.js. Либо открыть dist/index.html через расширение VS Code Live Server.

Не открывай index.html простым двойным щелчком: браузер блокирует JavaScript-модули на адресах file://. Сайт должен открываться через локальный HTTP-сервер или хостинг.

## Первый показ

- Mission control → Start inspection. Роботы начнут обследование. Speed 8× ускоряет показ.
- На карте выбери панель, нажми Examine: откроются измерения и вероятности диагнозов.
- Кнопка Disable отключает одного робота. Второй продолжит миссию.
- Apply thermal cycle изменяет скрытое состояние повреждений. Для обнаружения изменений нужны новые измерения.
- Repair lab: выбери панель и подходящее действие, нажми Execute & verify. Система проводит три новых измерения. Ремонт может не сработать.
- Benchmark → Reveal ground truth завершает слепой тест и показывает настоящие дефекты. До раскрытия экспорт не содержит их координаты.
- Run comparison запускает одинаковые наборы сценариев для двух стратегий. Экспорт CSV содержит результаты каждого опыта.
- Judge mode позволяет задать 1–2 дефекта, шум, начальный seed, бюджет, рост повреждений и доступные датчики.

Интерфейс на английском для международного показа. Подсказка How to run a mission содержит краткое пояснение на русском.

## Что реализовано

1. Интерактивная 3D-модель из 32 панелей: вращение, выбор, структурный вид, карта риска, каркас.
2. Четыре признака измерений: сдвиг резонанса, затухание, температура, деформация.
3. Байесовская диагностика: исправная панель, ослабленное крепление, расслоение, микротрещина.
4. Активный выбор следующей проверки: покрытие, неопределённость, соседство с аномалией.
5. Два робота: положение, расход энергии, время перемещения, отказ и восстановление.
6. Эволюция повреждений при обследовании и дополнительных температурных циклах.
7. Прогноз условной степени повреждения и диапазон сценариев.
8. Ремонт крепления, заплатка, усиление, снижение нагрузки, изоляция и повторная инспекция.
9. Три повторных измерения после ремонта, отдельная история проверки.
10. Режим судьи, раскрытие истины, матрица результатов текущей миссии.
11. Сравнение активной и последовательной стратегии на 20/40/100 воспроизводимых сценариях.
12. Выгрузка JSON-отчёта и CSV с результатами экспериментов.
13. Синтезированный звук отклика; по умолчанию выключен.
14. Локальные шрифты Cormorant Garamond и Manrope, локальная Three.js, адаптивная вёрстка, поддержка reduced motion.
15. Дополнительный read-only WebMCP-интерфейс при наличии поддержки браузера.

## Где менять код

- dist/index.html — страницы, тексты, формы.
- dist/style.css — оформление, размеры, адаптивность.
- dist/app.js — события интерфейса, графики, экспорт.
- dist/engine.js — генерация измерений, диагностика, роботы, ремонт, бенчмарк.
- dist/scene.js — 3D-модель и интерактивность.
- dist/fonts/ — шрифты, работающие без внешних запросов.
- dist/vendor/ — Three.js и её лицензия.
- tests/engine.test.mjs — автоматические проверки логики.
- docs/METHODOLOGY.md — устройство модели и ограничения.

## Проверка

```bash
npm test
```

Проверены воспроизводимость, обнаружение дефектов в штатном сценарии, отказ роботов, ошибочный и успешный ремонт, изоляция, отключение датчиков и одинаковый бюджет бенчмарка. Дополнительно выполнены проверки интерфейса в DOM-среде. Полная визуальная проверка в браузере с WebGL в среде сборки была недоступна; это не следует считать проверкой всех устройств.

## Размещение на своём хостинге

Размещай содержимое dist как статический сайт. Сборка не нужна. На GitHub Pages index.html должен быть в корне выбранной папки публикации: можно перенести содержимое dist в корень отдельного репозитория. На статическом хостинге укажи output directory: dist; build command оставь пустой. Все адреса ресурсов относительные, поэтому подпапки поддерживаются. Никакие ключи вводить не нужно.

## Честное описание для конкурса

Это **исследовательский симулятор с модельным ИИ**, а не обученная на реальных космических панелях нейросеть. Данные синтетические, функции изменения признаков упрощены. Байесовская модель знает общие законы симуляции, но не скрытые координаты и типы дефектов. Успех на синтетических опытах не доказывает работу на реальном материале. Для следующего этапа нужны реальные записи ударного/вибрационного отклика и независимая проверка на новых панелях.

Перезагрузка страницы сбрасывает состояние; сохраняй отчёты перед закрытием. Слепой режим отделяет состояние среды от политики, но не защищает от человека, который исследует код и память браузера.
